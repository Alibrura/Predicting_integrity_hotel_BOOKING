## 📌 Описание проекта

**Booking.com** — одна из ведущих мировых онлайн-платформ для бронирования отелей. Компания сталкивается с проблемой нечестных отелей, которые искусственно завышают свой рейтинг. Один из способов выявления таких отелей — построение модели, предсказывающей ожидаемый рейтинг отеля на основе объективных данных. Если фактический рейтинг значительно отклоняется от предсказанного, это может сигнализировать о недобросовестных действиях.

В данном проекте решается задача **регрессии**: необходимо предсказать оценку (`reviewer_score`), которую рецензент поставил отелю, используя набор данных с информацией об отзывах, характеристиках отеля и географических координатах.

---

## 🎯 Цель исследования

Создать модель машинного обучения, способную точно предсказывать рейтинг отеля, и тем самым помочь выявлять подозрительные заведения. Качественная предобработка данных и проектирование признаков (feature engineering) должны повысить точность модели.

## 📂 Данные

Исходный датасет `hotels.csv` содержит **386 803 строки** и **17 столбцов**. Описание признаков:

| Признак | Описание |
|--------|----------|
| `hotel_address` | Адрес отеля |
| `review_date` | Дата размещения отзыва (YYYY-MM-DD) |
| `average_score` | Средний балл отеля за последний год (на основе последнего комментария) |
| `hotel_name` | Название отеля |
| `reviewer_nationality` | Страна рецензента |
| `negative_review` | Текст отрицательного отзыва |
| `review_total_negative_word_counts` | Количество слов в отрицательном отзыве |
| `positive_review` | Текст положительного отзыва |
| `review_total_positive_word_counts` | Количество слов в положительном отзыве |
| `reviewer_score` | **Целевая переменная** – оценка, поставленная рецензентом (от 0 до 10) |
| `total_number_of_reviews_reviewer_has_given` | Сколько отзывов оставил рецензент в прошлом |
| `total_number_of_reviews` | Общее количество действительных отзывов об отеле |
| `tags` | Теги, присвоенные отелю рецензентом |
| `days_since_review` | Количество дней между датой отзыва и датой выгрузки данных |
| `additional_number_of_scoring` | Количество оценок без текстового отзыва |
| `lat` | Географическая широта отеля |
| `lng` | Географическая долгота отеля |

## 🧱 Этапы исследования

### 1. Исследование данных и проектирование признаков (Feature Engineering)

#### 1.1 Загрузка и первичный анализ
- Размерность: 386 803 × 17.
- Обнаружены пропуски в столбцах `lat` и `lng` (впоследствии заполнены реальными координатами).
- Удалено 307 дубликатов.
- 9 числовых столбцов, 8 текстовых; категориальных, кроме `tags`, не выявлено.

#### 1.2 Временные признаки
- Из `review_date` выделены `review_year` и `review_month`.
- Наибольшее количество отзывов приходится на летние месяцы, преобладают свежие отзывы.

#### 1.3 Текстовые признаки (тональность)
- С помощью VADER-анализа для каждого отзыва получены четыре метрики: доли негативных, нейтральных, позитивных слов и интегральная оценка `compound`.
- Созданы 8 признаков (по 4 для `negative_review` и `positive_review`):
  - `negative_review_neg`, `negative_review_neu`, `negative_review_pos`, `negative_review_compound`
  - `positive_review_neg`, `positive_review_neu`, `positive_review_pos`, `positive_review_compound`

#### 1.4 Категориальные признаки
- Национальность рецензента (`reviewer_nationality`) сгруппирована в категории: англоязычные, азиатские, мусульманские страны и прочие.
- Статистический тест подтвердил значимые различия в средних оценках между группами.

#### 1.5 Числовые признаки
- Дополнительно созданы шкалы сентимента `negative_scale` и `positive_scale` (диапазон от –1 до 1) на основе тональности отзывов.

#### 1.6 Географические признаки
- Исправлены пропуски в координатах; в дальнейшем можно добавить внешние данные (страна, регион, близость к достопримечательностям).

#### 1.7 Агрегированные признаки
- Для каждого отеля рассчитано медианное значение тональности (`negative_scale`, `positive_scale`) по всем его отзывам.
- Вычислено отклонение тональности конкретного отзыва от медианы отеля — новый признак, усиливающий влияние индивидуальной оценки.

### 2. Анализ и отбор признаков (Feature Selection)

#### 2.1 Анализ мультиколлинеарности
- Выявлены коррелирующие признаки; часть из них исключена для улучшения устойчивости модели.

#### 2.2 Отбор влиятельных признаков
- Применён **RFE (Recursive Feature Elimination)** с линейной регрессией.
- Отобрано **30 наиболее значимых признаков** для финальной модели.

### 3. Обучение модели и подбор параметров (Model Training)

- В качестве базового алгоритма выбран **RandomForestRegressor** – он хорошо работает с нелинейными зависимостями и устойчив к переобучению.
- Для оптимизации гиперпараметров использована библиотека **Optuna**.
- Оценка качества проводилась по метрике **MAPE (Mean Absolute Percentage Error)**.

### 4. Интерпретация результатов

- На тестовой выборке достигнуто значение **MAPE = 0.118 (11.8%)**.
- Это означает, что в среднем предсказанная оценка отклоняется от реальной на 11.8%, что является хорошим результатом для регрессионной задачи.

## 💡 Выводы и заключение

Целью исследования было создание модели машинного обучения для предсказания оценки (`reviewer_score`), которую рецензент ставит отелю. Задача регрессии успешно решена с помощью ансамблевого алгоритма **RandomForestRegressor** и тщательной инженерии признаков.

**Ключевые достижения:**
- Проведён глубокий разведывательный анализ, выявлены значимые закономерности (влияние национальности, сезонности, тональности отзывов).
- Созданы новые признаки на основе текстов (VADER-тональность) и агрегации по отелям (отклонение от медианы).
- Выполнен отбор признаков (RFE), что позволило снизить мультиколлинеарность и повысить качество.
- Оптимизация гиперпараметров с Optuna дала итоговую метрику **MAPE = 11.8%**, что является хорошим показателем.

**Практическая значимость:** модель может использоваться для автоматического выявления аномальных оценок и подозрительных отелей, помогая службе контроля качества Booking.com.
